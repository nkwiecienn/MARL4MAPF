# ICBS: Improved Conflict-Based Search Algorithm for Multi-Agent Pathfinding

Eli Boyarski CS Department Bar-Ilan University (Israel) eli.boyarski@gmail.com

Ariel Felner Roni Stern Guni Sharon ISE Department Ben-Gurion University felner@bgu.ac.il

David Tolpin Oded Betzalel Eyal Shimony CS Department Ben-Gurion University shimony@cs.bgu.ac.il

## Abstract

Conflict-Based Search (CBS) and its enhancements, *Meta-Agent CBS* and *bypassing conflicts* are amongst the strongest newly introduced algorithms for Multi-Agent Path Finding. This paper introduces two new improvements to CBS and incorporates them into a coherent, improved version of CBS, namely ICBS. Experimental results show that each of these improvements further reduces the runtime over the existing CBS-based approaches. When all improvements are combined, an even larger improvement is achieved, producing state-of-the art results for a number of domains.

## Introduction and Overview

A *Multi-Agent Path Finding* (MAPF) problem is defined by a graph,  $G = (V, E)$  and a set of  $k$  agents labeled  $a_1 \dots a_k$  where each agent  $a_i$  has a start position  $s_i \in V$  and a goal position  $g_i \in V$ . At each time step an agent can either *move* to an adjacent location or *wait* in its current location. The task is to plan a sequence of move/wait actions for each agent  $a_i$ , moving it from  $s_i$  to  $g_i$  such that agents do not *conflict*, i.e., occupy the same location at the same time, while aiming to minimize a cumulative cost function. MAPF has practical applications in video games, traffic control, robotics etc. (see Sharon et al. 2013; 2015 for a survey).

In this paper we focus on solving MAPF problems *optimally*, i.e., where the cost of the resulting plan must be minimized. There is a range of algorithms that optimally solve different variants of MAPF using various search techniques [Standley, 2010; Wagner and Choset, 2011; Sharon *et al.*, 2013] or by compiling it into other known NP-hard problems [Surynek, 2012; Yu and LaValle, 2013; Erdem *et al.*, 2013]. Each of these solvers has pros and cons, with no universal winner. Which algorithm performs best under what circumstances is an open research question.

*Conflict-Based Search* (CBS) [Sharon *et al.*, 2012a; 2015], is a very effective optimal MAPF solver. CBS has two-levels. The low-level finds optimal paths for the individual agents. If the paths include conflicts, the high level, via a *split* action (described below), imposes constraints on the conflicting agents to avoid these conflicts.

Two improvements to CBS were suggested. First, Metaagent CBS (MA-CBS) [Sharon *et al.*, 2012b; 2015] generalizes CBS by merging small groups of agents into meta-agents

when beneficial. The main merge policy is to merge agents for which the number of conflicts seen so far exceeds a given threshold  $B$ ; for good choices of  $B$ , MA-CBS reduces the runtime. Second, the *bypass* (BP) improvement to (MA)CBS (i.e., CBS with or without applying the optional merge action) was recently suggested [Boyarski *et al.*, 2015]. (MA)CBS arbitrarily chooses paths in the low-level. When BP is added on top of (MA)CBS we first try to find an alternative path (by-pass) for one of the conflicting agents thus avoiding the need to perform a split and to add new constraints. (MA)CBS+BP further reduces the running time. A variant of CBS that solves MAPF suboptimally also appeared [Barer *et al.*, 2014].

In this paper we introduce *Improved-CBS* (ICBS) which further adds two new improvements to (MA)CBS+BP. Each of these improvements is strongly tied to one of the former improvements (MA and BP) as follows:

- (1) **Merge and restart**. (**MR**) In MA-CBS, agents are merged locally at each node of the search tree. Instead, when a decision to merge is made, we suggest to restart the search from scratch, with the new merged meta-agent treated as a single agent for the entire search tree.
- **(2) Prioritizing conflicts.** (PC) (MA)CBS (even with BP added) arbitrarily chooses which conflict to split. Poor choices may increase the size of the high-level search tree. To remedy this, we prioritize the conflicts according to three types: *cardinal*, *semi-cardinal* and *non-cardinal*. Cardinal conflicts always cause an increase in the solution cost, so ICBS chooses to split cardinal conflicts first. Additionally, bypasses to cardinal conflict cannot exist. Therefore, the optional BP improvement [Boyarski *et al.*, 2015] should only be applied for semi- or non-cardinal conflicts.

All four enhancements to CBS (i.e., MA-CBS, BP, PC and MR) are optional and can be added separately or in conjunction with the others, except for MR which is only relevant to MA-CBS. In this paper we show how to combine them all into a coherent improved version of CBS, namely ICBS.

Experimental results show that MR and PC each provide a significant speedup over the previous best CBS variant, namely (MA)CBS+BP [Boyarski *et al.*, 2015]. Even further speedup is achieved when both improvements are combined and ICBS outperforms other related algorithms in many cases where previous variants of CBS performed poorly.

A <i>conflict</i> between two paths is a tuple <math>\langle a_i, a_j, v, t \rangle</math> where agent <math>a_i</math> and agent <math>a_j</math> are planned to occupy vertex <math>v</math> at time point <math>t</math>. A solution is <i>valid</i> if it is conflict-free. The <i>cost</i> of a path is the number of actions in it (including wait), and the cost of a solution is the sum of the costs of its constituent paths.</p><p>In CBS, agents are associated with constraints. A <i>constraint</i> for agent <math>a_i</math> is a tuple <math>\langle a_i, v, t \rangle</math> where agent <math>a_i</math> is prohibited from occupying vertex <math>v</math> at time step <math>t</math>. A <i>consistent path</i> for agent <math>a_i</math> is a path that satisfies <i>all</i> of <math>a_i</math>'s constraints, and a <i>consistent solution</i> is a solution composed of only consistent paths. Note that a consistent solution can be <i>invalid</i> if despite the fact that the paths are consistent with the individual agent constraints, they still have inter-agent conflicts.</p><p>The high-level of CBS searches the <i>constraint tree</i> (CT). The CT is a binary tree, in which each node <math>N</math> contains: <b>(1)</b> A set of constraints imposed on the agents (<i><math>N.constraints</math></i>), <b>(2)</b> A single solution (<i><math>N.solution</math></i>) consistent with these constraints, <b>(3)</b> The cost of <i><math>N.solution</math></i> (<i><math>N.cost</math></i>).</p><p>The root of the CT contains an empty set of constraints. BP is optionally added to the CBS pseudo code (lines 11-12 in Algorithm 1).</p><p><b>Example:</b> consider again the root <math>R_2</math> of Figure 2(III). <math>R_2</math> is split into two nodes as described above. In the left child <math>M</math> agent <math>a_1</math> finds path <math>P_1 = \langle S1, A, C, E, G1 \rangle</math>. However, <math>R_2</math> can <i>adopt</i> path <math>P_1</math> for agent <math>a_1</math>. <math>P_1</math> is a valid bypass because it does not include conflict <math>C_1 = \langle a_1, a_2, B, 1 \rangle</math> which caused the split. In addition, it is a helpful bypass because <math>R_2.NC = 2</math> (conflicts <math>C_1</math> and <math>C_2</math>) but after adopting the path from <math>M</math>, <math>R_2.NC</math> will decrease to 1 (conflict <math>C_3</math>). Now, instead of a CT with 5 nodes we get a CT with only 3 nodes.</p><p>While processing a node <math>N</math>, BP incurs no extra overhead due to peek operations. Basic CBS generates both children and adds both to OPEN. In the worst case when both peek operations fail, BP does exactly the same as CBS, i.e., generates and adds these children to OPEN. But if one of these nodes is found helpful then BP adds no new nodes to OPEN and might even avoid the need to generate and run a low-level search for the 2nd child if the first child includes a helpful bypass.</p><p>Additionally, note that node <math>N</math> in its "new suit", i.e., after adopting a path, will now be the best node in OPEN and will be chosen for expansion next.<sup>3</sup> Therefore, if it has a helpful child again then BP will be repeated here. In fact, the next <i>real</i> split will occur only when a bypass call fails.</p><h2>ICBS Improvement 2: Prioritize Conflicts (PC)</h2><h2>Drawbacks of (MA)CBS and (MA)CBS+BP</h2><p>To guarantee optimality, CBS expands nodes in a best-first order according to the cost function. While <math>A^*</math> expands <i>al</i> nodes with <math>f &lt; C^*</math> (= the optimal solution cost) to guarantee optimality of the solution no such <i>mandatory nodes</i> are known for CBS. Consequently, CBS (even with BP) is very sensitive to the conflicts chosen to <i>split</i> on, as these can significantly influence the number of CT nodes. In its basic form, CBS arbitrarily picks a conflict for splitting (e.g., the first one seen). This can lead to poor performance and CBS can be stuck in an area with similar cost as demonstrated below.</p><h3>Remedy: Splitting cardinal conflicts first</h3><p>To address this drawback we distinguish between three types of conflicts and show that prioritizing them may immediately increase the solution cost in the sub-tree below the current node thereby significantly reducing the size of the CT.</p><p></p><p><sup>3</sup>A mechanism like <i>immediate expand</i> [Stern <i>et al.</i>, 2010] which bypasses OPEN can can be efficiently activated here.</p><p block-type="ListGroup"><ul><li block-type="ListItem"><ul> • <b>(1) Cardinal conflict.</b> A conflict <math>C = \langle a_1, a_2, v, t \rangle</math> is <i>cardinal</i> for a CT node <math>N</math> if adding any of the two constraints derived from <math>C</math> (<math>\langle a_1, v, t \rangle</math>, <math>\langle a_2, v, t \rangle</math>) to <math>N</math> and invoking the low-level on the constrained agent, the cost of its path is increased when compared to its cost in <math>N</math>. An equivalent definition is that <math>C</math> is <i>cardinal</i> if all the consistent optimal paths for both <math>a_1</math> and <math>a_2</math> include location <math>v</math> at time step <math>t</math>. For example, in Figure 1(I) the conflict <math>\langle a_1, a_2, C, 2 \rangle</math> is cardinal. None of the agents has a path to its goal of length 3 which doesn't pass through <math>C</math> in time step 2. Therefore, one of these agents must travel more than three steps in order to resolve this conflict. </ul></li><li block-type="ListItem"><ul> (2) <b>Semi-cardinal conflliction.</b> A conflict <math>C = \langle a_1, a_2, v, t \rangle</math> is <i>semi-cardinal</i> for a CT node <math>N</math> if adding one of the two constraints derived from <math>C</math> increases <math>N.cost</math> but adding the other leaves <math>N.cost</math> unchanged. Equivalently, <math>C</math> is <i>semi-cardinal</i> if all the consistent optimal paths of one agent include location <math>v</math> at time step <math>t</math>, but the other agent has such a path that does not include <math>v</math> at time step <math>t</math>. For example, the conflict <math>\langle a_1, a_2, B, 1 \rangle</math> in Figure 1(I) is semi-cardinal (assuming the paths are <math>P_1 = \langle S_1, B, C, G_1 \rangle</math> and <math>P_2 = \langle S_2, B, C, G_2 \rangle</math>). <math>a_2</math> must use <math>B</math> at time step 2, but <math>a_1</math> can choose <math>A</math> instead. </ul></li><li block-type="ListItem"><ul><b>(3) Non-cardinal conflict.</b> A conflict <math>C = \langle a_1, a_2, v, t \rangle</math> is <i>non cardinal</i> for a CT node <math>N</math> if <b>neither</b> of the two constraints derived from <math>C</math> causes an increase of <math>N.cost</math>. For example, in Figure 1(I), if the dotted lines (path through <math>D</math>) are enabled then the conflict <math>\langle a_1, a_2, B, 1 \rangle</math> is non-cardinal. Now agent <math>a_2</math> can choose to go via node <math>D</math> at the same cost.</ul></li></ul></p><p>We now make the following observations: (1) If a cardinal conflict exists for CT node <math>N</math> then the cost of a valid solution below <math>N</math> must be greater than <math>N.cost</math>. (2) In any best-first search increasing a lower bound of a node in OPEN is beneficial as this lower bound is more informed.</p><h4>Prioritization of conflicts (PC):</h4><p>This new improvement works as follows. When a node <math>N</math> with <math>N.cost = c</math> is chosen for expansion by CBS, we examine all its conflicts. If a cardinal conflict is encountered, it is immediately chosen for the split action. This generates two children with <math>cost &gt; c</math>. In this case if another node <math>N'</math> in OPEN has <math>cost &lt; c</math>, then <math>N'</math> can be immediately chosen for expansion next without further developing nodes below <math>N'</math>. In contrast, if a cardinal conflict exists but instead we choose a semi-cardinal or a non-cardinal conflict, we may generate a large subtree below <math>N</math> with the same cost <math>c</math>. Furthermore, the cardinal conflict will reappear in all of the nodes in the subtree below <math>N</math> until it is chosen and resolved.</p><p>To illustrate this, consider again Figure 1(I) (assuming the paths chosen at <math>R1</math> are <math>P'_1 = \langle S_1, B, C, G_1 \rangle</math> and <math>P_2 = \langle S_2, B, C, G_2 \rangle</math>). Two conflicts exist in the root node: a semi-cardinal conflict <math>C_1 = \langle a_1, a_2, B, 1 \rangle</math> and a cardinal conflict <math>C_2 = \langle a_1, a_2, C, 2 \rangle</math>. If <math>C_2</math> were chosen (Figure 1(II)) the</p><p>costs increase immediately and thend the left child is declared as the goal. In contrast, Figure 1(III) illustrates the case where <math>C_1</math> is chosen. In a simple implementation, it will be chosen as it is seen first. In its left child <math>M</math> the constraint <math>(a_1, B, 1)</math> is added and <math>a_1</math> will choose the path <math>P_1 = \langle S_1, A, C, G_1 \rangle</math>. However, the cardinal conflict <math>C_2</math> still exists and will be again chosen for a split. There are 5 nodes in the corresponding CT (Figure 1(III)). In contrast, the CT of Figure 1(II) has 3 nodes.</p><p>If no cardinal conflicts exist, the next preference is to choose semi-cardinal conflicts. Here, we know that the cost of at least one child will immediately increase. Finally, if only non-cardinal conflicts exist, one of them is chosen arbitrarily. PC is shown in line 9, where we seek a cardinal/semi-cardinal conflict. [Boyarski <i>et al.</i>, 2015] suggested to apply BP for <i>every</i> conflict. However, in this paper we note that valid bypasses (with the same cost) can only be found for <i>semi-</i> or <i>non-cardinal conflicts</i> but not for <i>cardinal conflicts</i>. Therefore, in ICBS BP is applied more conservatively: with a cardinal conflict, we jump to line 13 and BP is not activated.</p><p>Otherwise (only semi- or non-cardinal conflicts were found) we continue with the pseudo code allowing to perform BP on</p><p>the chosen conflict.</p><h4>Identifying a cardinal conflict using MDDs</h4><p>The <i>multi-value decision diagram</i> <math>MDD_i^c</math> [Sharon <i>et al.</i>, 2013] is a DAG which compactly stores all possible paths of given cost <math>c</math> for a given agent <math>a_i</math> while completely ignoring the other agents. Nodes of the MDD can be distinguished by their depth below the source node. Every node at depth <math>t</math> of <math>MDD_i^c</math> corresponds to a possible location of <math>a_i</math> at time <math>t</math> that is on a path of cost <math>c</math> from <math>s_i</math> to <math>g_i</math>. <math>MDD_i^c</math> has a single <i>source node</i> at level 0, corresponding to agent <math>a_i</math> located at <math>s_i</math> at time <math>t_0</math>, and a single <i>sink node</i> at level <math>c</math>, which corresponds to agent <math>a_i</math> located at <math>g_i</math> at time <math>t_c</math>. The nodes of <math>MDD_1^3</math> which corresponds to paths of length 3 for agent <math>a_1</math> have a small black circle in their lower part in Figure 1(I).</p> <p><b>Observation:</b> If, for a CT node <math>N</math> with <math>N.cost = c</math>, there exists a cardinal conflict <math>C</math> of the form <math>\langle a_i, a_j, D, t \rangle</math>, then the widths of <math>MDD_i^{c_i}</math> and <math>MDD_j^{c_j}</math> at time-step <math>t</math> must be 1.</p><p>Therefore, to find cardinal conflicts in CT node <math>N</math> we iterate over all conflicts <math>C</math> in <math>N</math> and test each conflict <math>C = \langle a_i, a_j, D, t \rangle</math> for cardinality by building <math>MDD_i^{c_i}</math> and <math>MDD_j^{c_j}</math> (<math>c_i</math> is the cost of path of <math>a_i</math> in <math>N.cost</math>) and checking whether their width at depth <math>t</math> is 1. This is repeated until a cardinal conflict is found or all the conflicts in <math>N</math> have been checked. If no cardinal conflict is found, a semi cardinal conflict is chosen if it was encountered during the iteration. Otherwise, a non-cardinal conflict is arbitrarily chosen.</p><p>Maintaining and checking all MDDs incurs an overhead per CT node. But, this pays off in dense environments with many bottlenecks where many cardinal conflicts exist.<sup>5</sup></p><p><b>Meta-agent conflicts.</b> Building an MDD for meta-agents is expensive. Therefore in our implementation for MA-CBS we first build MDDs for meta-agents of size 1 (individual agents) which participate in a conflict. If a cardinal conflict was not</p><p></p><p><sup>4</sup>Based on this, our optimized implementation pushes <math>N</math> back into OPEN with the new cost without even generating the two children. This proved beneficial in our experiments.</p><p></p><p><sup>5</sup>In a practical implementation MDDs can be reused from parents when applicable. In addition, to find a cardinal conflict quickly, we check MDDs of agents in decreasing order of the number of conflicts in which they participate.</p><p><img src="_page_5_Figure_0.jpeg"/></p><p>Figure 3: CBS variants: (a) success rate (b) runtime and nodes.
